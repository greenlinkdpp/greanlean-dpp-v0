# UI/UX页面和交互验收基线

## 1. 原则

- 复用当前Greanlean视觉设计和组件库；
- 不因为本文件重新设计全部品牌界面；
- 移动端重点保障公共扫码页，后台以桌面端为主并可基本响应式；
- 页面上的完整率、验证状态和Registry状态必须来自后端，不由前端自行推导；
- 所有阻断信息可点击定位到字段、证据或任务。

## 2. 公共前台

### 2.1 首页

P0要求：

- 首屏明确聚焦电池护照；
- 展示户储和LMT两个入口；
- 按钮：适用性评估、单型号试点、资料清单、案例；
- 演示案例显著标注演示/模拟/未核验边界；
- 3次点击内完成评估申请。

### 2.2 适用性评估表单

字段至少包括：企业、联系人、产品类别、用途、额定能量、欧盟销售情况、投放主体、现有资料、目标时间、同意免责声明。

提交后输出初步结果、缺失信息和下一步，不直接给出不可撤销法律结论。

### 2.3 公共护照页

- 通过HTTPS UPI访问；
- 显示产品身份、版本号、发布时间、状态和数据验证说明；
- 数据按分区展示；
- 非公众字段不存在于HTML初始数据和API响应；
- PDF/JSON下载显示同一版本；
- 撤回或替代时明确提示；
- 移动端扫码可用；
- 页面404/失效/归档有清晰状态，不能泄露内部ID。

## 3. 后台导航

建议最小导航：

1. 总览；
2. 项目；
3. 产品/护照；
4. 资料导入；
5. 证据中心；
6. 审核与发布；
7. Registry；
8. 组织与成员；
9. 配置/Schema（受控）；
10. 审计与运维（受控）。

实际可映射现有菜单。

## 4. 项目工作台

### 4.1 项目总览

必须展示：项目状态、范围、负责人、时间、产品数量、字段完整率、证据完整率、阻断项、待审核、最近活动和里程碑。

### 4.2 适用性

展示问卷输入、规则版本、初步判断、待确认问题、责任人、顾问/客户确认记录和免责声明。

### 4.3 产品层级

树或清晰层级显示Model、Batch、BatteryItem；能看出继承、覆盖、单体唯一标识和发布状态。批量创建前提供预览和冲突检查。

### 4.4 数据与缺口

- 按分组、状态、责任人、证据、访问级别过滤；
- 字段显示来源、继承层级、原始值、规范单位、验证状态；
- 缺口导出；
- 跨字段错误直接定位；
- 批量操作必须预览和可撤销/有审计。

### 4.5 证据

- 列表和详情；
- 文件类型、编号、签发方、日期、适用范围、哈希、状态；
- 关联字段/产品；
- 到期提醒；
- 受限下载；
- 新版本不覆盖旧文件。

### 4.6 审核与发布

- 提交前展示门禁结果；
- 审核人可按字段和证据退回；
- 批准后显示版本预览；
- 发布前确认UPI、公众投影、PDF、JSON和变更原因；
- 发布成功后显示不可变版本和输出哈希；
- 修改已发布内容必须创建新草稿。

### 4.7 Registry

- 显示组织准备度、UPI预检、环境、Feature Flag；
- 测试与生产状态明显区分；
- 提交记录、correlation ID、错误和URI；
- 无官方URI时不出现“注册成功”样式。

## 5. 导入体验

- 下载与当前Schema版本匹配的模板；
- 上传后先预检，不直接写入；
- 展示总行、成功、警告、失败；
- 错误定位到工作表、行、列、字段和原值；
- 用户确认后提交；
- 重复上传可幂等或明确覆盖策略；
- 后台异步任务可查询和重试失败行。

## 6. 可访问性和提示

- 状态不能只靠颜色；
- 表单错误与字段关联；
- 图表提供数值文本；
- 键盘可操作核心流程；
- 中英文文案不混用；
- 所有日期显示时区或统一规则；
- “企业声明”“第三方验证”“演示数据”使用统一术语。
