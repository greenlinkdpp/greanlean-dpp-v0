# 技术设计输出规格

Codex必须基于真实仓库形成 `docs/generated/TECHNICAL_DESIGN.md`，而不是照抄本文件。

## 1. 设计内容

### 1.1 当前与目标架构

- 系统上下文和部署拓扑；
- 前后端、数据库、对象存储、队列、缓存和第三方服务；
- 公共护照解析与后台管理的隔离；
- 现有模块和新增模块；
- 同步/异步边界；
- 失败恢复和重试。

### 1.2 数据架构

- 复用、新增、变更、废弃实体；
- Model-Batch-Item继承方案；
- 字段定义与值存储方案；
- 发布快照方案；
- 证据和文件版本；
- 时序数据冷热分层；
- 审计和软删除；
- 多租户隔离；
- 索引和容量假设。

### 1.3 应用架构

- 项目工作台；
- 资料采集和导入；
- 数据校验；
- 证据中心；
- 审核和发布；
- 页面/PDF/JSON投影；
- UPI路由和二维码；
- Registry适配器；
- 权限服务；
- 后台任务。

### 1.4 API与事件

- 版本策略；
- 错误模型；
- 幂等；
- 分页、过滤和排序；
- 文件上传；
- 批量导入；
- 审计事件；
- Webhook/异步任务状态。

### 1.5 安全

- 身份认证；
- 组织/租户/资源级授权；
- 文件访问；
- 加密；
- 日志脱敏；
- 密钥管理；
- 输入和文件校验；
- 审计日志保护。

### 1.6 兼容与迁移

- 旧DPP页面和ID如何映射；
- 现有数据如何补齐Organisation/Model/Item；
- 无序列号历史案例如何标记演示或型号展示；
- URL重定向；
- 双写或灰度；
- 回滚路径。

## 2. 设计决策记录

每个重要决策至少包含：

- 问题；
- 现有事实；
- 选项；
- 选择；
- 原因；
- 影响；
- 回滚方式；
- 待验证项。

## 3. 禁止设计

- 用前端隐藏代替鉴权；
- 用可变业务表直接充当发布版本；
- 所有字段写死在页面组件；
- 以GTIN/SGTIN字符串直接冒充HTTPS UPI；
- Registry调用和业务发布强耦合到无法关闭；
- 文件公开永久URL无鉴权；
- 以JSON大字段逃避关键唯一约束和关联完整性；
- 在不清楚现有生产数据时创建破坏性迁移。
