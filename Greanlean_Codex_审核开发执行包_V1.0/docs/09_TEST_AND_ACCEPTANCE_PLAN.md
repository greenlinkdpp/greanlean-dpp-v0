# 测试与验收计划

## 1. 测试层级

### 单元测试

- 继承/覆盖解析；
- 单位转换；
- ID-001/002、BAT-001/002、MAT-001、EVD-001、TIM-001、REG-001、PUB-001；
- 权限投影；
- 状态机转换；
- 快照哈希；
- Registry响应判定。

### 集成测试

- 数据库唯一约束和事务；
- 文件上传、哈希、EvidenceLink；
- 导入任务和错误；
- 草稿审核发布；
- 页面/PDF/JSON生成；
- 组织隔离；
- 旧URL重定向；
- Registry Mock/Test适配器。

### E2E

- 户储样例从项目到发布；
- LMT样例从导入到发布；
- 公众扫码；
- 专业用户授权访问；
- 证据到期后新发布受阻；
- 已发布版本更正；
- Registry失败和成功边界。

### 安全测试

- 跨租户ID猜测；
- 文件直链；
- 导出越权；
- 前端隐藏字段通过API读取；
- 批量导入公式/脚本注入；
- 恶意MIME/扩展名；
- SSRF/开放重定向（UPI和外部链接）；
- 日志敏感信息。

## 3. 额外必测场景

- 两租户使用相同serial_number：允许或禁止按需求约束；当前基线是组织内唯一；
- 同租户重复serial_number：数据库层拒绝；
- 同一UPI跨租户重复：全局拒绝；
- Batch绑定错误Model：拒绝；
- 并发编辑同一草稿：检测row_version冲突；
- 审核者直接修改已提交字段：按角色和流程拒绝或生成退回；
- Publisher绕过Approve：拒绝；
- 删除被发布版本引用的Evidence：拒绝物理删除；
- PDF生成失败：发布事务回滚或保持可重试状态；
- 公共页面缓存：版本切换后不返回旧敏感投影；
- UPI旧链接：发布新版本后仍解析同一Item当前有效版本；
- 导入部分失败：成功行策略明确，失败可重试且幂等。

## 4. 质量门

P0不得发布，除非：

- 所有CRITICAL/HIGH审查问题已解决或书面接受；
- 数据迁移在副本/测试库演练；
- 核心测试全部通过；
- 多租户越权测试通过；
- T01-T06、T08、T10通过；T07/T09可按P1 Feature Flag处理；
- 页面/PDF/JSON同源校验自动化；
- 回滚步骤已验证或有可恢复备份；
- 测试报告写明实际命令和结果。

## 5. 测试数据规则

只使用`fixtures/`中的合成数据。不得复制网站真实案例中的可能识别企业、人员、证书或序列号。合成数据必须显式标记`DEMO/SYNTHETIC`。
