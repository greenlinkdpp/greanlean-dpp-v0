# Codex代码审查清单

按严重度输出问题，优先报告会导致错误行为、数据损坏、越权或不可恢复问题。不要把纯样式偏好与真实缺陷混在一起。

## 数据与迁移
- [ ] 迁移是否可能删除/覆盖生产数据；
- [ ] 唯一约束是否只在应用层；
- [ ] Model/Batch/Item外键是否可交叉租户；
- [ ] 发布版本是否仍能被UPDATE；
- [ ] 软删除是否破坏唯一性或历史引用；
- [ ] 回填是否凭空生成事实数据；
- [ ] 回滚是否可行。

## 权限与安全
- [ ] 每个资源查询是否同时约束organisation；
- [ ] 导出、文件、PDF/JSON是否绕过字段权限；
- [ ] 公共API是否泄露内部ID、草稿或敏感字段；
- [ ] 支持人员是否默认全租户访问；
- [ ] 上传是否校验类型、大小、哈希和恶意内容；
- [ ] 日志/错误是否含秘密或客户资料；
- [ ] UPI是否存在开放重定向、SSRF或路径注入。

## 工作流和一致性
- [ ] 是否能直接PATCH状态绕过提交/审核/发布；
- [ ] 审核/发布并发是否产生重复版本；
- [ ] 页面/PDF/JSON是否来自同一快照；
- [ ] 证据到期是否只改旧版本；
- [ ] 导入和批量创建是否幂等；
- [ ] 跨字段校验是否在服务端执行；
- [ ] 错误是否能定位字段和对象。

## Registry
- [ ] 是否可手工写REGISTERED；
- [ ] 无URI是否被标成功；
- [ ] Test/Mock是否混入Production；
- [ ] 是否保留请求哈希、响应和correlation ID；
- [ ] 凭据是否被记录或提交。

## 测试
- [ ] 是否测试数据库约束而非只Mock；
- [ ] 是否有跨租户负面测试；
- [ ] 是否测试已发布版本不可变；
- [ ] 是否测试权限投影和导出；
- [ ] 是否测试失败和重试；
- [ ] 是否运行而不是只编写测试。
