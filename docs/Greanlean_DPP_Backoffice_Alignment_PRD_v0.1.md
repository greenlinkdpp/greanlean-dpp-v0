# Greanlean DPP 后台与展示一致化产品需求

> 文件类型：产品需求文档（PRD）  
> 目标版本：Greanlean v0.6.0 - Unified DPP Backoffice  
> 文档版本：v0.1  
> 日期：2026-07-25  
> 状态：待确认，本阶段仅输出需求，不执行代码、数据库或线上修改  
> 前置版本：Greanlean v0.5.0 - Unified DPP Platform

---

## 0. 执行结论

本次后台重构不能继续以“增加更多表单”为目标，而应建立一套与最终 DPP 页面、权限投影、发布版本和外部接口完全一致的产品工作区。

核心决策如下：

1. 一个产品只保留一个后台工作区；
2. 后台主体按最终 DPP 页面的九个一级模块组织；
3. 行业、品类和细分模板必须在创建产品时先确定；
4. 五个行业共用同一工作流，行业差异通过字段配置产生；
5. 电池保留型号、批次、单体、动态数据和生命周期事件能力，但不再形成另一套孤立后台；
6. “保存草稿”和“发布 DPP”必须是两个不同操作；
7. 发布时必须把产品及全部关联数据组装成完整、不可变的发布快照；
8. 网页、PDF、机器可读 JSON 和二维码必须引用同一发布版本；
9. 公开、专业、监管和内部预览必须来自同一字段记录的权限投影；
10. 证据状态、验证状态、数据来源、责任人和可见范围必须成为所有重要字段的标准元数据；
11. Registry、区块链和审计记录属于系统操作，不允许普通用户手工伪造；
12. 动态电池数据通过 BMS、EMS、网关、维保或受控人工记录进入，不与静态产品字段混填；
13. 后台不直接显示法规长字段清单给普通录入人员，法规字段由业务模块映射和准备度检查承接；
14. 只有真实文件、真实交易和真实外部响应才能标记为已上传、已锚定或已注册；
15. 所有写操作最终经服务器权限、事务、校验和审计执行。

# 一、产品背景

## 1.1 前台已经形成的目标能力

Greanlean v0.5.0 已形成统一 DPP 展示体系：

```text
产品身份与制造信息
材料与组成
环境与可持续性
性能、耐久性与安全
行业专属模块
供应链与生产追溯
合规声明与证据文件
维修、循环利用和生命周期结束
生命周期事件与更新
```

页面支持：

- 公众访问；
- 合法利益主体访问；
- 监管访问；
- 内部预览；
- 中英文；
- GS1 标识与二维码；
- PDF 与机器可读数据；
- 电池运行快照、历史趋势和生命周期事件；
- 数据库发布版本；
- 服务器权限投影。

后台需要成为这些能力的唯一维护入口，而不是继续使用与前台结构不同的历史表单。

## 1.2 本次重构目标

形成以下完整业务链路：

```text
创建产品
→ 选择行业、品类、细分模板和数据粒度
→ 系统生成适用模块与字段
→ 按九个 DPP 模块维护产品数据
→ 上传并关联证据
→ 检查中英文、来源、证据、验证和权限
→ 预览四种受众结果
→ 提交内部审核
→ 生成完整发布快照
→ 发布网页、二维码、PDF 和 JSON
→ 按需准备 Registry 映射
→ 发布后持续追加生命周期和电池运行数据
```

# 二、当前后台现状

## 2.1 已有能力

当前系统已经具备以下基础：

- 创建产品时选择行业、产品类别和细分模板；
- 产品基础信息维护；
- GTIN、批次、序列号和数字链接维护；
- 材料、BOM、ESG、追溯、循环性、证书和文档表；
- 行业字段模板及字段值；
- 电池 BatteryPass-Ready 字段目录；
- 电池型号、批次、单体和动态指标；
- 产品版本和 SHA-256 Hash；
- Registry TEST 适配；
- 访问申请和审批；
- 审计表和区块链锚定表；
- 公开、专业和监管预览入口。

这些能力可以复用，不需要推倒数据库重新开始。

## 2.2 主要问题

### 问题 1：后台结构与最终页面不一致

后台仍按基础信息、数字身份、材料、组件、ESG、消费者透明度、法规字段、Registry、审计、区块链等历史数据表顺序展开。

结果：

- 用户不知道某个字段最终显示在哪里；
- 同类信息分散在多个位置；
- “行业字段”和“业务数据”看起来重复；
- 页面过长，无法判断完成进度；
- 电池与其他行业使用不同的编辑体验。

### 问题 2：保存版本不是完整 DPP 版本

当前产品基本信息保存时生成的版本快照主要包含 `products` 记录，不自动包含刚修改的：

- 材料；
- BOM；
- ESG；
- 追溯；
- 循环性；
- 证书和文档；
- 行业字段；
- 数据治理；
- 电池静态字段。

最终 DPP 页面优先读取已发布版本快照，因此可能出现：

```text
后台关联数据已更新
≠
前台已发布内容已更新
```

这是本次重构的最高优先级问题。

### 问题 3：草稿、审核和发布混在一个表单

当前一个保存动作同时承担：

- 更新产品；
- 选择生命周期状态；
- 填写版本号；
- 填写变更类型；
- 生成 Hash；
- 写入产品版本。

普通数据维护不应自动产生可被前台读取的发布版本。

### 问题 4：通用行业与电池后台双轨

电池使用 BatteryPass 字段工作区，其他行业使用通用关联表管理器。

问题不在于电池有专属字段，而在于：

- 导航逻辑不同；
- 发布入口不同；
- 准备度算法不同；
- 证据关联方式不同；
- 预览位置不同；
- 用户会理解成两套产品。

目标应是统一工作区内的“电池行业扩展模块”。

### 问题 5：多个入口可以修改同一类数据

材料、ESG、证书既可以在产品详情中维护，也存在快录或导入入口。

需要明确：

- 产品工作区是单产品权威入口；
- 快录是批量录入工具；
- 导入是暂存和映射工具；
- 所有入口写入同一草稿数据模型；
- 快录和导入不得绕过校验直接发布。

### 问题 6：部分操作过于接近数据库管理

当前部分页面允许直接填写：

- Registry 请求和响应 JSON；
- 审计日志；
- 区块链交易 Hash；
- 锚定状态；
- 证据引用记录 ID；
- 内部技术字段。

普通用户不应手工维护这些系统记录。

### 问题 7：存在产生误导性系统记录的风险

区块链锚定目前可以自动生成形式上像真实交易的 Hash。未来必须调整为：

- 未连接真实区块链时只能显示“未配置”或“等待锚定”；
- 只有链上服务返回真实交易后才能保存交易 Hash；
- 失败、重试和确认数必须来自真实连接器；
- 不得生成模拟交易并在业务页面当作成功记录。

### 问题 8：发布预览和真实权限容易混淆

后台需要预览公众、专业和监管页面，但：

- 预览只应对内部管理员开放；
- 预览结果不是对外授权结果；
- 外部用户仍由登录身份、组织、角色和产品授权决定；
- URL 参数不能提高权限。

### 问题 9：文件仍以 URL 录入为主

最终系统需要真正的文件管理：

- 上传；
- 存储；
- 下载权限；
- Hash；
- 文件版本；
- 到期状态；
- 字段映射；
- 病毒和格式检查；
- 不同受众下载权限。

仅输入 URL 无法完整承接证据治理。

### 问题 10：产品创建标识规则过弱

当前创建产品时可生成随机 DPP ID，但没有完整区分：

- 内部产品 ID；
- DPP ID；
- GTIN；
- 型号级 UPI；
- 批次级 UPI；
- 单体级 UPI；
- GS1 Digital Link；
- Registry 返回标识。

标识应由粒度和 GS1 数据规则统一生成或校验。

# 三、版本目标与非目标

## 3.1 版本目标

本版本包括：

- 统一后台信息架构；
- 与九个前台模块一一对应的产品工作区；
- 五行业模板；
- 电池五个重点配置及适用性判断；
- 字段元数据和证据状态；
- 模块准备度；
- 中英文完整度；
- 完整草稿聚合；
- 内部审核；
- 完整发布快照；
- 发布前差异对比；
- 四种受众预览；
- 访问申请与授权管理；
- 电池动态数据管理；
- 文件上传与证据映射；
- Registry TEST 准备；
- 真实区块链锚定接口边界；
- 系统审计；
- 批量导入与供应商协同边界；
- 数据迁移、回滚和测试方案。

## 3.2 本版本不包括

- 自动判断企业已经满足全部法规；
- 自动签发证书或检测报告；
- 伪造第三方验证结论；
- 正式 EU Registry 生产提交；
- 未经确认的最终行业授权法案字段；
- 秒级 BMS 监控平台；
- 替代 EMS、SCADA、ERP、PLM 或 LIMS；
- 自动连接所有区块链；
- 未经审批自动公开供应商敏感数据；
- 为五个行业分别开发五套后台；
- 通过 URL 参数给予真实专业或监管权限。

# 五、后台信息架构

建议后台导航调整为：

```text
工作台

数据任务
批量导入
供应商协同
```

说明：

- 数据粒度；
- 工作流状态；
- 当前草稿版本；
- 当前发布版本；

- 证据准备度；

- 行业；
- 品类；
- 模板；

# 六、产品创建流程

## 6.1 第一步：适用性与分类

必填：

- 行业；
- 产品类别；
- 细分类；
- DPP 模板版本；
- 型号/批次/单体粒度；
- 目标市场；
- 责任经济运营者；
- 是否计划对外发布。

选择结果决定：

- 九个模块中哪些适用；
- 字段必填、条件必填或不适用；
- 字段单位和枚举；
- 默认可见范围；
- 推荐证据类型；
- 准备度规则；
- Registry 映射；
- 电池动态数据策略。

## 6.2 第二步：产品最小身份

创建草稿仅要求：

- 产品名称；
- 内部 SKU/型号；
- 品牌或制造商；
- 英文主名称；
- 中文名称可暂缺；
- 产品负责人。

创建后由服务器生成：

- 内部产品 UUID；
- 草稿 DPP ID；
- 工作区；
- 初始任务；
- 初始模板绑定；
- 审计记录。

## 6.3 标识生成策略

系统必须区分：

| 标识 | 用途 |
|---|---|
| 内部 UUID | 数据库主键，不公开 |
| DPP ID | Greanlean 护照稳定标识 |
| GTIN | GS1 产品标识 |
| 批次号 | 批次粒度 |
| 序列号 | 单体粒度 |
| UPI | 对外唯一产品标识 |
| GS1 Digital Link | 二维码解析地址 |
| Registry ID | 外部注册库返回标识 |

规则：

- 用户可录入已有 GTIN；
- 系统验证 GTIN 长度和校验位；
- 未具备 GTIN 时可先建立草稿，但不能标记 GS1 就绪；
- UPI 根据数据粒度生成；
- 已发布的 UPI 不允许直接覆盖；
- 标识变更通过新版本或新产品关系处理；
- 二维码始终指向稳定解析地址。

# 七、统一产品工作区

## 7.1 页面结构

```text
产品工作区头部
├── 产品名称、DPP ID、行业和模板
├── 草稿状态、发布状态、当前版本
├── 总体准备度和阻断项
└── 保存草稿、提交审核、内部预览、发布

左侧模块导航
├── 01 产品身份与制造信息
├── 02 材料与组成
├── 03 环境与可持续性
├── 04 性能、耐久性与安全
├── 05 行业专属模块
├── 06 供应链与生产追溯
├── 07 合规声明与证据文件
├── 08 维修、循环利用和生命周期结束
├── 09 生命周期事件与更新
└── 10 检查、预览与发布

右侧状态栏
├── 必填完整度
├── 条件字段完整度
├── 证据完整度
├── 验证完整度
├── 中英文完整度
├── 受众配置
└── 发布阻断项
```

|---|---|---|
| 产品身份与制造 | 名称、型号、品牌、GTIN、UPI、批次、序列号、运营者、制造地 | 01 产品身份与制造信息 |
| 材料与组成 | 材料、质量占比、BOM、再生成分、来源、化学信息 | 02 材料与组成 |

| 行业专属 | 电池、纺织、家具、建材、消费电子字段 | 05 行业专属模块 |

## 11.1 准备度维度

## 11.2 发布阻断项

以下情况阻止发布：

- 没有行业或模板；
- 没有稳定 DPP ID；
- 必填标识缺失；
- 必填字段缺失；
- 必填证据缺失；

- 历史数据新鲜度不足；

# 十二、审核、预览与发布

## 12.1 状态模型

### 产品工作流状态

- 草稿；
- 数据采集中；
- 待审核；
- 审核驳回；
- 可发布；
- 已发布；
- 更新中；
- 已归档。

### 发布版本状态

- 构建中；
- 校验失败；
- 待批准；
- 已发布；
- 已取代；
- 已撤回；
- 已过期。

### Registry 状态

独立维护：

- 未准备；
- 本地校验；
- TEST 文件已生成；
- TEST 已提交；
- TEST 已接受；
- TEST 已拒绝；
- PRODUCTION 未启用；
- PRODUCTION 已提交；
- PRODUCTION 已接受。

产品状态、发布状态和 Registry 状态不能共用一个字段。

## 12.2 保存草稿

保存草稿：

- 更新工作数据；
- 运行字段校验；
- 写入审计；
- 不改变公开页面；
- 不生成新的公开版本；
- 不触发区块链；
- 不宣称 Registry 已更新。

## 12.3 提交审核

提交审核时：

- 锁定待审核数据集；
- 生成审核候选快照；
- 运行阻断校验；
- 记录与当前发布版本的差异；
- 通知审核员；
- 编辑修改后自动退回草稿或产生新候选。

## 12.4 内部预览

内部预览提供：

- 公众版；
- 专业版；
- 监管版；
- 机器可读 JSON；
- PDF；
- 二维码目标。

预览页必须标注：

- 内部预览；
- 候选版本；
- 未发布；
- 当前模拟受众。

预览通过服务器生成，不使用可被外部用户利用的前端提权参数。

## 12.5 发布

发布必须执行单一服务器事务或可恢复工作流：

```text
读取审核通过的数据
→ 聚合产品及全部关联数据
→ 应用行业模块映射
→ 应用字段可见性
→ 构建完整发布快照
→ 生成规范化 JSON
→ 计算 SHA-256
→ 保存不可变 product_version
→ 更新当前发布指针
→ 生成网页/PDF/JSON 引用
→ 写入审计
→ 可选触发 Registry TEST 或真实区块链锚定
```

发布版本至少包含：

- 产品；
- 数字身份；
- 材料；
- BOM；
- 环境数据；
- 性能数据；
- 行业字段；
- 追溯；
- 循环性；
- 消费者说明；
- 证书；
- 文档；
- 证据映射；
- 数据治理；
- 发布元数据；
- 权限投影规则；
- 电池公开静态投影。

电池单体动态数据不复制到公众发布快照，通过授权动态投影读取。

## 12.6 更新和回滚

- 已发布版本不可编辑；
- 更新从当前版本创建新草稿；
- 发布前显示字段级差异；
- 回滚不是覆盖旧版本，而是基于历史版本创建新的恢复版本；
- 二维码和稳定 UPI 不变；
- 撤回必须记录原因和责任人；
- 专业和监管访问审计继续保留。

# 十三、Registry、审计与区块链

## 13.1 Registry

后台 Registry 页面只提供：

- 当前准备度；
- 映射版本；
- 操作规则版本；
- TEST 文件生成；
- 本地验证结果；
- 提交记录；
- 外部响应；
- 错误和重试。

用户不直接编辑提交 JSON 和响应 JSON。系统根据发布版本自动生成。

在官方电池语义目录未开放时：

- 可以生成 TEST 映射文件；
- 可以记录人工测试结果；
- 不得显示“正式注册成功”；
- PRODUCTION 操作保持禁用。

## 13.2 审计

审计由服务器自动追加：

- 登录；
- 数据创建、修改和删除；
- 文件上传；
- 证据状态变化；
- 审核决定；
- 发布、撤回和恢复；
- 权限申请和审批；
- Registry 操作；
- 设备凭据创建和轮换；
- 动态数据接入异常；
- 区块链锚定。

审计记录：

- 只追加；
- 不允许客户端创建任意内容；
- 不允许修改或删除；
- 保存操作人、组织、时间、对象、前后 Hash、请求关联 ID 和必要上下文。

## 13.3 区块链

区块链只锚定已发布版本的 Hash，不保存整份产品数据。

流程：

```text
已发布版本
→ 获取不可变 SHA-256
→ 调用真实区块链连接器
→ 返回交易 Hash
→ 等待链上确认
→ 保存链、网络、区块、时间和浏览器地址
```

状态：

- 未配置；
- 待提交；
- 已提交；
- 确认中；
- 已确认；
- 失败；
- 已取代。

没有真实连接器时不得生成交易 Hash。

## 17.1 中文后台

- DPP、GTIN、SGTIN、UPI、BMS、EMS、LCA、EPD、REACH、WEEE 等标准缩写可保留；
- 数据库字段代码只在高级信息中显示；
- 不在中文标签后重复英文解释；
- 法定企业名称、型号和标准编号保持原文。

## 17.2 录入体验

- 一屏聚焦一个模块；
- 不嵌套多层卡片；
- 批量数据用表格或可编辑列表；
- 复杂字段使用侧边编辑面板；
- 保存状态始终可见；
- 离开未保存页面时提醒；
- 长流程自动保存草稿；
- 错误定位到具体字段；
- 模块导航显示完成状态；
- 手机可查看和审批，复杂批量录入以桌面端为主。

## 17.3 空状态

- 不适用：明确说明由模板判断；
- 待填写：显示负责人和截止时间；
- 待证据：提示建议文件；
- 待审核：显示提交时间；
- 未接设备：显示接入指引；
- Registry 未开放：显示官方依赖，不暗示系统故障。

# 十八、验收标准

## 18.1 一致性

- 九个后台模块与九个最终展示模块一一对应；
- 后台字段可以明确定位到公众、专业或监管页面；
- 同一字段不在普通界面重复录入；
- 电池和其他行业使用同一工作区骨架；
- 五行业使用配置产生差异；
- 网页、PDF 和 JSON 使用同一发布版本；
- 发布后页面内容与发布预览一致。

## 18.2 发布

- 保存草稿不改变公开页面；
- 发布前显示阻断项；
- 发布生成完整多表快照；
- 发布版本不可修改；
- 版本 Hash 可重算验证；
- 可比较任意两个版本；
- 回滚通过新版本实现；
- 旧二维码继续访问稳定产品。

## 18.3 权限

- 外部修改 URL 不能提权；
- 内部预览只有内部角色可用；
- 供应商只能访问被分配数据；
- 专业和监管访问按组织、角色、产品和有效期计算；
- 公开 API 不返回受限字段；
- 所有敏感操作有审计。

## 18.4 证据

- 文件真实存在才能显示下载；
- 文件上传自动计算 Hash；
- 证据可映射多个字段；
- 验证状态只能由授权角色修改；
- 文件过期产生任务和发布警告；
- 已发布文件不会被原位覆盖；
- 系统不自动生成虚假报告、签章或认证。

## 18.5 电池

- 五个重点电池配置可选择；
- 便携式和 SLI 不被错误标记为同一护照要求；
- 型号、批次和单体关系清晰；
- 动态指标只追加；
- 最新值、历史和事件一致；
- 初始化数据不显示为实时设备数据；
- 公众不读取单体动态数据；
- 授权用户可读取允许范围；
- 接入凭据不可回读明文。

## 18.6 Registry、区块链和审计

- Registry 文件来自已发布版本；
- 未开放官方能力时不显示正式注册成功；
- 审计记录不可编辑；
- 区块链只锚定已发布 Hash；
- 没有真实链上返回时不生成交易 Hash；
- 锚定失败不影响 DPP 页面读取，但产生告警和重试任务。

## 18.7 技术质量

- TypeScript、构建、单元、集成、迁移和权限测试通过；
- 关键发布流程具备端到端测试；
- 数据迁移可回滚；
- 无密钥进入浏览器或 Git；
- 中英文和响应式检查通过；
- 线上 Preview 人工验收后再发布 Production。

# 二十一、风险与控制

| 风险 | 控制 |
|---|---|
| 重构造成现有 DPP 页面数据丢失 | 先做只读聚合层和映射，保留旧表与旧版本 |
| 字段统一后丢失行业特色 | 统一工作区骨架，行业字段继续配置化 |
| 普通用户仍觉得字段太多 | 只显示适用字段，按模块、角色和优先级渐进展示 |
| 草稿误发布 | 草稿、审核、发布三阶段分离 |
| 前台继续显示旧快照 | 发布服务聚合全部关联数据并更新当前发布指针 |
| 假文件或假证书 | 文件真实存在、Hash 和审核状态独立 |
| 模拟区块链被误认为真实 | 未配置连接器时禁止生成交易 Hash |
| 动态数据被误解为实时 | 显示采样方式、新鲜度和来源，不默认使用“实时” |
| Registry 能力被过度承诺 | TEST/PRODUCTION 隔离，官方依赖明确显示 |
| 供应商看到敏感数据 | 字段级任务、组织隔离和产品范围授权 |
| 法规字段变化 | 模板版本化，发布版本保留所用模板版本 |

# 二十二、待确认产品决策

建议默认采用以下决策：

1. 目标版本为 v0.6.0；
2. 先实施 P0，不同时启动供应商门户和真实区块链；
3. 产品工作区按九个最终展示模块组织；
4. 电池作为行业扩展嵌入统一工作区；
5. 草稿保存不更新公开页面；
6. 只有审核通过后才能生成发布版本；
7. 发布快照是网页、PDF、JSON 和 Registry 的唯一版本来源；
8. 文件改为真实上传，URL 仅作为外部证据补充；
9. 审计完全只读；
10. 没有真实区块链连接器时关闭锚定提交；
11. 五行业同时保留，但首批实施和验收优先覆盖电池、纺织和消费电子；
12. 家具和建材字段在授权法案未最终确定前使用“准备字段/待确认”状态。

```text
阶段 0：字段与数据映射
```

阶段 0 只输出字段映射、数据库影响和迁移计划，经确认后再开始业务代码重构。
