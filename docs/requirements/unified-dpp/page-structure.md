# Greanlean 统一官网与 DPP 页面结构

日期：2026-07-24
目标版本：v0.5.0
文档类型：阶段 0 页面结构与实现边界
依据：统一 DPP 平台重构 PRD 和现状影响分析

## 1. 页面体系

目标页面体系分为四层：

```text
官网
├── 全局 DPP 平台
├── 行业方案
├── 电池护照专题
├── 法规与时间线
└── 四个产品护照案例

统一 DPP 页面
├── 公众投影
├── 合法利益主体投影
├── 监管投影
└── 内部预览

后台
├── 产品和分类
├── 行业字段
├── 证据与版本
├── 权限和访问
└── 电池动态数据接入

接口
├── GS1 Digital Link
├── DPP 网页、PDF 和 JSON
├── Registry 适配
└── BMS、EMS、网关和维保接入
```

官网负责解释平台和引导案例，DPP 页面负责展示产品，后台负责数据维护。三者不应在同一个组件中混合。

## 2. 官网结构

### 2.1 顶部导航

桌面端：

```text
[Greanlean]
首页
DPP 平台
行业方案
电池护照
产品护照案例
法规与时间线
联系我们
[中 / EN]
```

移动端：

- 品牌；
- 语言切换；
- 菜单按钮；
- 展开后显示全部导航；
- 当前锚点有清晰状态；
- 菜单关闭后焦点返回菜单按钮。

### 2.2 首页模块顺序

#### A. 全局 DPP Hero

目标：

- 第一屏明确 Greanlean 是全行业 DPP 平台；
- 不把工业电池当成唯一产品；
- 展示真实产品或多行业 DPP 页面画面；
- 主要操作指向案例和平台流程。

内容：

```text
面向欧盟市场的数字产品护照平台
行业模板、产品数据、证据、GS1 标识、权限和生命周期更新统一管理

[查看产品护照案例] [了解平台流程]
```

Hero 下方应露出下一模块的一部分，避免首屏成为独立海报。

#### B. 法规与实施进度

横向或可横向滚动的时间线：

- ESPR 生效；
- DPP Registry 实施安排；
- 电池护照适用日；
- 纺织品预计授权法案采纳；
- 家具预计授权法案采纳；
- 消费电子相关横向措施。

每个节点必须包含：

- 日期；
- 日期性质；
- 产品范围；
- 一句话说明；
- 官方来源入口。

日期性质使用：

- 已确定；
- 预计采纳；
- 待正式适用日期；
- 待实施文件。

#### C. 平台工作流程

六步横向流程：

1. 判断适用性；
2. 选择行业和粒度；
3. 采集数据与证据；
4. 建立标识和权限；
5. 发布网页、二维码和机器可读数据；
6. 持续更新生命周期。

移动端改为垂直步骤，不使用过度装饰卡片。

#### D. 行业方案

固定五个行业：

- 电池；
- 纺织品；
- 家具；
- 建材；
- 消费电子。

每项显示：

- 法规状态；
- 产品分类；
- 数据模块；
- 平台支持状态；
- 对应案例或“方案准备中”。

行业项使用同一网格和高度，不为电池设计一套完全不同的卡片。

#### E. 电池护照重点板块

这是首页唯一可以明显加强视觉权重的行业板块。

结构：

```text
电池护照
├── 适用范围
│   ├── LMT
│   ├── EV
│   └── 大于 2 kWh 的工业电池
├── 核心数据
│   ├── 身份
│   ├── 材料与碳
│   ├── 性能与耐久
│   ├── 维修与安全
│   └── 运行状态与健康
├── 数据更新方式
│   ├── BMS/EMS
│   ├── 设备网关
│   └── 维保快照
└── 2027-02-18 时间节点
```

必须说明：

- 护照不等于秒级监控；
- 平台保存最新快照、历史趋势和生命周期事件；
- 受限动态数据需要身份授权。

#### F. 四个产品护照案例

顺序：

1. LMT 电池；
2. 工业储能电池；
3. 纺织品；
4. 消费电子。

统一卡片结构：

```text
[同一比例产品图片]
[行业] [产品类别]
产品名称
一句产品说明
关键指标 1
关键指标 2
关键指标 3
能力标签 x 3
[查看产品护照]
```

卡片禁止显示：

- Demo；
- 演示；
- 合成；
- 100% 合规；
- 已获欧盟认证；
- 没有证据支持的“已验证”。

#### G. 平台能力

使用紧凑图标列表或分栏：

- 行业模板；
- 数据采集；
- 供应商协同；
- GS1 标识；
- 证据和版本；
- 身份和权限；
- Registry 准备；
- API 和生命周期更新。

#### H. 可信度边界

说明五类状态：

- 企业声明；
- 文件支持；
- 第三方验证；
- 待补充；
- 不适用。

该模块不是免责声明墙，应简洁解释平台不会自动生成认证结论。

#### I. 联系和页脚

联系表单保留，字段应包括：

- 企业；
- 联系人；
- 邮箱；
- 产品行业；
- 产品数量；
- 当前资料状态；
- 需求说明。

页脚保留：

- 平台；
- 行业；
- 法规；
- 案例；
- 后台登录；
- 隐私和联系方式。

## 4. 一级模块顺序

所有产品使用以下顺序：

1. 产品身份与制造信息；
2. 材料与组成；
3. 环境与可持续性；
4. 性能、耐久性与安全；
5. 行业专属模块；
6. 供应链与生产追溯；
7. 合规声明与证据文件；
8. 维修、循环利用和生命周期结束；
9. 生命周期事件与更新。

空模块规则：

- 无任何适用字段：不显示；
- 字段适用但待补充：显示一个紧凑的“待补充”状态；
- 字段不适用：专业/审计视图可显示“不适用”，公众视图不占位；
- 不允许自动生成看似真实的内容填满页面。

## 6. 受众投影

### 6.1 一个二维码

```text
一个物理二维码
→ 一个稳定 UPI
→ 服务器解析产品
→ 未登录：PUBLIC
→ 已登录：根据组织、角色和产品范围计算权限
→ 同一页面框架返回不同字段
```

二维码不携带角色，也不区分消费者码、采购码和监管码。

### 6.2 公众

可见：

- 产品身份；
- 主要材料；
- 基础环境信息；
- 使用和护理；
- 维修和回收；
- 公开证据；
- 公开生命周期信息。

不可见：

- 详细配方；
- 受限供应商；
- 单体运行数据；
- 内部审批；
- 受限检测文件；
- Registry 操作记录；
- 区块链后台交易细节。

### 6.3 合法利益主体

登录后可见：

- 详细材料和部件；
- 维修和拆卸；
- 受限运行快照；
- 供应链信息；
- 专业文件；
- 数据来源和验证状态。

### 6.4 监管主体

强身份验证后可见：

- 完整法规字段；
- 证据映射；
- Registry 记录；
- 受限文件；
- 验证状态；
- 数据治理和审计信息。

### 6.5 内部预览

后台可以预览四个受众结果，但必须明确：

- 预览不是实际授权；
- 预览入口只对内部管理员开放；
- `view` 查询参数不参与真实权限计算；
- 外部用户无法通过修改 URL 提权。

## 7. 电池运行状态与健康

### 7.1 模块位置

位于“性能、耐久性与安全”之后、“供应链与生产追溯”之前。

公众页面只显示：

- 是否支持持续更新；
- 最后更新日期；
- 数据访问说明。

不显示单体遥测值。

专业和监管页面按权限显示数据。

### 7.2 最新快照

布局为固定四列指标网格，优先显示：

- SOC；
- SOH；
- 剩余容量；
- 剩余可用能量；
- 完整循环次数；
- 温度；
- 内阻变化；
- 能量吞吐量。

每项包含：

- 数值；
- 单位；
- 测量时间；
- 来源；
- 质量状态；
- 新鲜度。

不得显示“实时”，除非接口确实提供实时通道并定义实时阈值。

### 7.3 历史趋势

图表支持：

- 24 小时；
- 7 天；
- 30 天；
- 12 个月；
- 全生命周期。

默认：

- LMT：30 天；
- 工业储能：7 天；
- 无连续数据时：显示事件或维保快照时间线。

### 7.4 生命周期事件

时间线事件：

- 投入使用；
- 维护；
- 检查；
- 故障；
- 安全事件；
- BMS 更换；
- 维修；
- 改变用途；
- 梯次利用；
- 退役；
- 回收。

### 7.5 初始化数据

在未接设备时：

```text
data_source = INITIAL_DATASET
verification_status = UNVERIFIED
source_device = INITIAL-IMPORT
```

前台用语：

- 初始记录；
- 最近记录；
- 数据来源；
- 尚未接入自动更新。

不得用：

- 实时；
- BMS 已连接；
- 设备已验证；
- 第三方认证。

## 8. 数据 ViewModel

页面组件不得直接理解数据库表。

建议统一输入：

```ts
type PublicDppViewModel = {
  identity: DppIdentity;
  heroMetrics: DppMetric[];
  sections: DppSectionModel[];
  audience: "PUBLIC" | "LEGITIMATE_INTEREST" | "AUTHORITY_ONLY" | "INTERNAL";
  publication: DppPublication;
  qr: DppQrModel;
  downloads: DppDownload[];
};
```

数据流：

```text
Supabase
→ Public DPP Repository
→ Published Version Resolver
→ Audience Projector
→ Sector Module Mapper
→ PublicDppViewModel
→ UnifiedDppPage
```

网页、PDF 和 JSON 必须从同一个发布版本生成。

## 9. 行业模块配置

建议配置：

```ts
type SectorModuleConfig = {
  sectorCode: string;
  moduleOrder: string[];
  heroMetricCodes: string[];
  visibleSections: string[];
  labels: Record<"zh" | "en", Record<string, string>>;
};
```

页面不能再依赖：

- 特定 DPP ID；
- 特定 public slug；
- 产品名称正则；
- `isDemoProduct`；
- 产品专属 JSX。

## 10. 路由策略

唯一权威地址：

```text
/p/[DPP_ID 或稳定 UPI 标识]
```

兼容地址：

```text
/demos/lmt-battery
/demos/industrial-battery
/products/green-vault-ess-14-3
/passports/[legacy-slug]
```

兼容地址只做重定向。

重定向目标默认不带：

- `view=professional`；
- `view=audit`；
- `preview=1`。

语言可以保留：

- `lang=zh`；
- `lang=en`。

## 11. 中英文规则

中文页面：

- 标题、说明、按钮和状态均为中文；
- DPP、GTIN、SGTIN、BMS、EMS、WEEE、REACH 等正式缩写可保留；
- 缩写第一次出现时提供中文含义；
- 产品型号、标准编号和企业法定名称不强制翻译；
- 不显示英文说明作为中文注释。

英文页面：

- 不混入中文状态；
- 中国地址可以提供英文转写；
- 中文法定企业名称可作为补充，不替代英文主要字段。

所有标签从同一内容结构读取，禁止在 JSX 中散落重复中英字典。

## 12. 折叠和导航

- 一级模块默认展开；
- 长列表和技术明细可以折叠；
- 展开按钮显示“展开”；
- 收起按钮显示“收起”；
- 图标方向必须随状态变化；
- `aria-expanded` 和 `aria-controls` 必须正确；
- 页面锚点导航不放在卡片内；
- 移动端锚点导航横向滚动；
- 固定导航不能遮挡模块标题。

## 13. 响应式要求

断点原则：

- 手机：单列；
- 平板：两列；
- 桌面：内容与产品侧栏分栏；
- 宽屏：内容宽度受限，不无限拉伸。

固定格式：

- 图片比例稳定；
- 二维码固定正方形；
- 指标网格固定最小高度；
- 按钮文字不溢出；
- 长标识可以换行；
- 表格在手机端切换为键值列表或横向滚动；
- 图表在手机端保留可读坐标。

## 14. 组件拆分顺序

阶段 2 建议按以下顺序拆分：

1. `PublicDppViewModel`；
2. `UnifiedDppPage`；
3. Header 和 Hero；
4. Section Navigation；
5. 通用字段与文件组件；
6. 通用一级模块；
7. 行业专属模块；
8. 受众提示；
9. 电池健康模块；
10. 旧页面兼容层。

`PublicDppClient` 在迁移期间作为兼容入口，四个案例全部迁移后再删除旧分支。
