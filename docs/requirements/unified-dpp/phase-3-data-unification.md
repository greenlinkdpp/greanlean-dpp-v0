# 统一 DPP 平台阶段 3：数据统一实施记录

日期：2026-07-25  
目标版本：v0.5.0  
阶段状态：已完成并通过线上只读复核

## 1. 实施结论

四个重点产品的公开页面、PDF 和 JSON 已收敛到同一个数据库读取入口：

```text
产品标识或历史别名
→ products
→ 最新 product_versions 发布快照
→ UnifiedDppPage / PDF / JSON
```

发布快照不存在时，系统仅为尚未执行迁移的数据库读取既有产品关联表，不再生成整套静态产品内容。

## 2. 本阶段完成内容

- 新增统一公开数据仓库 `lib/dpp/publicDppRepository.ts`；
- `/p/[slug]`、后台预览和 `/api/dpp-export` 共用同一读取逻辑；
- 删除纺织品、消费电子和工业电池的页面静态补全；
- 删除工业电池专属页面组件和 TypeScript 静态产品模型；
- 删除产品中心的“同步演示数据”按钮及完整产品常量；
- 新增旧 DPP ID、旧 Slug 到正式产品的数据库别名；
- 将四个产品统一发布为 `v2.0` 数据库快照；
- 清除纺织和消费电子记录中的伪造证书编号、签发机构及文件 URL；
- 上述证据统一调整为 `pending`，不再显示为第三方已验证；
- 为工业储能电池补充材料、BOM、ESG、证据状态、追溯、循环性、身份和文件记录；
- 发布快照保存 SHA-256 数据哈希；
- 迁移保存变更前备份，并提供对应回滚 SQL。

## 4. 数据可信度处理

行业常规值可以作为企业声明或筛查估算记录，但不得伪装成第三方结论。

本阶段采用以下状态：

- 产品、材料、性能和流程信息：企业声明；
- 碳足迹：筛查估算，等待第三方核验；
- 证书和检测文件：待提供证据；
- 供应链组织名称：待核验；
- Registry 注册成功：未声明；
- 电池运行遥测：不进入公众发布快照。

## 5. 执行顺序

1. 在 Supabase SQL Editor 中一次性运行：
   `supabase/migrations/0012_unified_dpp_publications.sql`
2. 运行只读验收：
   `supabase/bundles/unified_dpp_publications_verify.sql`
3. 确认所有结果均为 `passed = true`；
4. 本地检查四个正式 DPP ID；
5. 再部署 Vercel Preview，人工验收后部署 Production。

不要把迁移文件拆成多段执行。迁移包含事务、临时构建函数和一致性检查。

## 6. 回滚

回滚文件：

`supabase/rollbacks/0012_unified_dpp_publications.down.sql`

回滚会恢复迁移前保存的产品、身份、证据、ESG、追溯、消费者信息和文件字段，并删除本阶段新增的工业电池关联记录、发布快照和别名表。

当 `v2.0` 已经产生新的业务修改时，应优先停止发布并进行前向修复，不应直接执行回滚。
