# DPP 完整发布快照与受众投影契约

日期：2026-07-25  
状态：阶段 0 技术基线  
适用范围：电池、纺织、家具、建材、消费电子

## 1. 目的

本契约定义 DPP 从领域数据到正式发布版本的唯一数据链路，确保：

- 后台录入字段与最终 DPP 展示模块一致；
- 网页、PDF、机器可读 JSON、二维码和 Registry 映射引用同一发布版本；
- 公众、专业客户、监管机构和内部人员看到的是同一份完整快照的不同权限投影；
- 已发布版本不可被后续草稿修改；
- 电池动态数据与静态发布快照分离，但仍绑定到同一产品、批次或单体；
- 证据、审计和完整性信息可以追溯。

## 2. 核心定义

### 2.1 领域数据

领域数据是后台可维护的当前事实，分散在产品、数字身份、材料、环境、性能、行业字段、追溯、证据、循环性、生命周期和电池专用表中。

领域数据可以处于草稿状态，不直接代表已经对外发布。

### 2.2 审核候选

审核候选是提交审核时由服务器聚合的规范数据。它用于：

- 执行字段、证据、权限和行业规则校验；
- 与当前已发布版本比较；
- 形成审核意见；
- 阻止审核期间数据被静默替换。

审核候选不是公开版本。

### 2.3 完整发布快照

完整发布快照是发布时由服务器生成并冻结的规范 DPP 数据包。它包含本次发布所需的所有适用字段、字段元数据、证据引用、权限等级和完整性信息。

完整快照不是“公开字段集合”，而是所有受众投影的唯一上游来源。

### 2.4 受众投影

受众投影是在读取时依据身份、组织关系、合法利益和字段权限，从完整发布快照中过滤出的结果。

统一权限等级：

| 等级 | 代码 | 典型受众 |
|---|---|---|
| 公开 | `PUBLIC` | 消费者、匿名访问者 |
| 合法利益 | `LEGITIMATE_INTEREST` | 买家、维修商、回收商、供应链伙伴 |
| 监管专用 | `AUTHORITY_ONLY` | 市场监管、海关、获授权机构 |
| 内部 | `INTERNAL` | 产品所有者、审核员、平台管理员 |

投影只能降低可见范围，URL 参数、前端开关或下载类型不能提升权限。

## 3. 权威数据链路

```text
领域数据表
→ 服务器聚合器
→ 规范字段模型
→ 审核候选
→ 发布校验
→ 完整不可变快照
→ SHA-256 内容摘要
→ 当前发布指针
→ 身份与权限投影
→ 网页 / PDF / JSON / Registry 映射
```

电池动态数据使用独立链路：

```text
BMS / EMS / 网关 / 维保系统 / 受控人工录入
→ 服务器接入与设备鉴权
→ 追加式运行指标和生命周期事件
→ 产品、批次或单体绑定
→ 授权动态投影
```

  "schemaVersion": "1.0.0",

    "dppId": "DPP-LMT-BAT-48V15AH",
    "version": 3,

    "publishedBy": "uuid",

## 5. 九个规范模块

完整快照只使用以下九个一级业务模块。行业差异通过字段适用性和 `sector` 模块处理，不再复制整套页面。

| 顺序 | 模块 | 内容 |
|---|---|---|
| 1 | `identity` | 产品、DPP、经营者、制造商、生产地点和唯一标识 |
| 2 | `materials` | 材料、组件、物质、质量占比、来源和材料声明 |
| 3 | `environment` | 碳足迹、再生含量、资源和其他适用环境指标 |
| 4 | `performance` | 产品性能、耐久性、测试指标和使用条件 |
| 5 | `sector` | 电池、纺织、家具、建材或消费电子专属字段 |
| 6 | `traceability` | 供应链、生产、批次、单体和关键事件 |
| 7 | `evidence` | 证书、报告、声明、文件版本和验证状态 |
| 8 | `circularity` | 可维修性、拆解、回收、再利用和生命周期结束信息 |
| 9 | `lifecycle` | 发布后追加的维修、转移、召回、再制造和退役事件引用 |

## 6. 规范字段对象

快照中的可展示字段统一使用下列逻辑结构：

```json
{
  "code": "battery.rated_capacity",
  "value": 15,
  "unit": "Ah",
  "display": {
    "zh": "15 Ah",
    "en": "15 Ah"
  },
  "label": {
    "zh": "额定容量",
    "en": "Rated capacity"
  },
  "accessLevel": "PUBLIC",
  "applicability": "APPLICABLE",
  "verificationStatus": "VERIFIED",
  "sourceType": "MANUFACTURER_DECLARATION",
  "sourceRecord": {
    "table": "battery_field_value",
    "id": "uuid"
  },
  "evidenceIds": ["uuid"],
  "updatedAt": "2026-07-25T11:30:00Z"
}
```

### 6.1 必需属性

- `code`：稳定、唯一、可映射到法规或行业模型的字段代码；
- `value`：机器可读原始值；
- `accessLevel`：字段最低访问等级；
- `applicability`：是否适用于当前产品；
- `verificationStatus`：验证状态；
- `sourceType`：数据来源类型；
- `sourceRecord`：权威来源记录引用。

### 6.2 条件属性

- 有单位的数值必须提供 `unit`；
- 需要展示的文字必须提供适用语言；
- 法规必填且需要证明的字段必须关联 `evidenceIds`；
- 复合对象必须使用结构化值，不允许把 JSON 对象转成可见字符串；
- 不适用字段记录原因，不以空字符串冒充不适用。

## 7. 受众投影规则

### 7.1 公众投影

公众投影用于扫码后的默认 DPP 页面。

包含：

- 产品识别和品牌；
- 消费者可理解的材料、环境、性能和循环信息；
- 公开证据摘要与可公开文件；
- 使用、维修、回收和安全信息；
- 公开生命周期事件；
- 二维码所指向的稳定 DPP URL。

不包含：

- 内部评审记录；
- 供应商保密信息；
- 原始 Registry 请求和响应；
- 设备凭证、内部接口信息；
- 完整审计日志；
- 默认的机器可读 JSON 下载按钮。

### 7.2 合法利益投影

在公众投影基础上，可包含：

- 供应链角色可见信息；
- 专业维修、拆解和回收资料；
- 受限测试报告；
- 批次级或单体级追溯信息；
- 经授权的电池动态指标和趋势；
- 专业客户机器可读数据下载。

必须满足服务端身份和关系授权，不能只凭链接访问。

### 7.3 监管投影

在合法利益投影基础上，可包含：

- 法规字段全集；
- 证明材料和验证状态；
- 经济运营者、制造商和责任主体信息；
- 发布、审核、变更和完整性记录；
- Registry 映射与提交结果；
- 经法律允许的运行和生命周期数据。

### 7.4 内部投影

内部投影用于后台编辑、审核和运维。它可以包含：

- 全部字段和内部备注；
- 草稿与已发布版本差异；
- 数据来源和缺失原因；
- 接入、验证、Registry、审计和锚定状态。

内部投影不等于可直接对外导出的 DPP。

## 8. 发布状态与操作

### 8.1 数据状态

| 状态 | 说明 |
|---|---|
| `DRAFT` | 可编辑，不影响公开页面 |
| `IN_REVIEW` | 已生成审核候选，等待审核 |
| `CHANGES_REQUESTED` | 审核退回 |
| `APPROVED` | 审核通过，可发布 |
| `PUBLISHED` | 已发布且不可修改 |
| `SUPERSEDED` | 已被新版本取代，仍可追溯 |
| `WITHDRAWN` | 已撤回，保留审计和历史版本 |

产品业务状态、发布状态和 Registry 状态必须分别存储。

### 8.2 保存草稿

保存草稿：

- 更新领域数据；
- 执行基础格式校验；
- 写入审计记录；
- 不生成正式发布版本；
- 不更新当前发布指针；
- 不改变公众页面；
- 不触发 Registry 或区块链。

### 8.3 提交审核

提交审核：

- 锁定或标识审核候选的数据基线；
- 构建规范候选快照；
- 运行法规、行业、证据、语言和权限校验；
- 生成与当前发布版本的字段级差异；
- 保存校验结果和审核任务。

### 8.4 发布

发布必须由服务器事务或可恢复工作流执行：

```text
确认审核状态
→ 锁定产品发布操作
→ 聚合全部权威来源
→ 运行发布阻断校验
→ 生成完整规范快照
→ 规范化序列化
→ 计算 SHA-256
→ 写入不可变发布版本
→ 更新当前发布指针
→ 生成或失效受众投影缓存
→ 写入审计记录
→ 异步生成 PDF / Registry 映射 / 锚定任务
```

任一步失败时，不得留下指向半成品版本的当前发布指针。

## 9. 完整性与 Hash

### 9.1 Hash 范围

内容摘要应覆盖：

- `schemaVersion`；
- `publication` 中除运行时生成字段以外的发布元数据；
- `classification`；
- 九个规范模块；
- `evidenceIndex`；
- `audienceManifest`；
- `governance`。

`integrity` 对象本身不参与自身 Hash。

### 9.2 规范化

计算 Hash 前必须：

- 使用 UTF-8；
- 按字段名稳定排序；
- 不依赖数据库返回顺序；
- 数值保持数值类型；
- 日期统一为 UTC ISO 8601；
- 数组按业务定义排序，不能按偶然查询顺序；
- 不包含临时签名 URL、当前登录人和页面参数。

示例：

```json
{
  "algorithm": "SHA-256",
  "canonicalization": "JCS",
  "digest": "hex-value",
  "generatedAt": "2026-07-25T12:00:00Z",
  "anchorStatus": "NOT_CONFIGURED"
}
```

### 9.3 区块链边界

- Hash 可以在未接入区块链时生成；
- 未发送真实交易时不得生成伪交易 Hash；
- 锚定状态至少区分 `NOT_CONFIGURED`、`PENDING`、`CONFIRMED`、`FAILED`；
- 区块链交易 ID 只能由受信适配器写入；
- 锚定失败不修改已发布快照，只追加状态记录和重试记录。

## 10. 证据与文件

- 快照保存证据记录和文件版本引用，不保存临时下载地址；
- 已发布版本引用的文件不可物理覆盖；
- 替换文件必须创建新文件版本，并在下一次 DPP 发布中引用；
- 文件的访问权限不得低于其关联字段；
- 文件删除采用保留历史的撤销或归档状态；
- 证书数量不是首页默认核心指标，首页展示应使用对消费者或专业受众更有意义的产品事实。

## 11. 电池动态数据边界

### 11.1 不进入静态快照的数据

以下数据通常持续变化，不复制到完整静态发布快照：

- 当前荷电状态；
- 当前健康状态；
- 电压、电流、温度；
- 充放电循环次数；
- 最近测量时间；
- 故障和告警；
- 运行历史趋势；
- 新增维修和生命周期事件。

### 11.2 静态快照保存的动态数据契约

静态快照只保存：

- 动态数据是否适用；
- 数据粒度：型号、批次或单体；
- 指标目录版本；
- 数据来源类型；
- 最近接入状态摘要；
- 允许哪些受众读取；
- 动态投影 API 版本。

### 11.3 动态读取

动态数据读取必须：

- 服务端鉴权；
- 验证用户与组织关系；
- 按产品、批次或单体限制；
- 返回数据时间戳、来源和质量状态；
- 不因 `view`、`preview` 或 `lang` 参数提升权限；
- 记录敏感数据访问审计。

## 12. 多渠道一致性

| 渠道 | 数据来源 | 版本规则 |
|---|---|---|
| DPP 网页 | 当前发布版本的受众投影 | 显示明确版本或更新时间 |
| PDF | 指定发布版本的固定投影 | PDF 内记录 DPP ID、版本和 Hash |
| JSON | 指定发布版本的机器投影 | 使用同一 schemaVersion |
| 二维码 | 稳定 DPP URL | 不直接编码临时文件或登录令牌 |
| Registry | 指定发布版本的映射结果 | 保存映射版本、请求摘要和响应 |

不同渠道可以有不同布局，但不能各自维护业务字段。

## 13. Registry 映射边界

- Registry 映射是完整快照到外部语义目录的确定性转换；
- 映射输入必须记录 `publicationId`、快照 Hash、映射规则版本和环境；
- TEST 和生产环境严格分开；
- 官方目录未开放时只能标识“映射准备完成”或“测试完成”；
- Registry 请求、响应、错误和重试由系统写入；
- 普通用户不能手工创建“成功”记录；
- Registry 返回结果不反向覆盖完整发布快照。

## 14. API 契约

建议的服务端能力：

| 能力 | 说明 |
|---|---|
| `buildDraftProjection` | 从领域表聚合后台工作区 |
| `createReviewCandidate` | 创建审核候选和差异 |
| `validatePublication` | 执行发布阻断与警告规则 |
| `publishDpp` | 生成不可变版本并更新当前指针 |
| `getPublishedProjection` | 按身份输出受众投影 |
| `getBatteryOperatingProjection` | 输出授权动态数据 |
| `generatePublicationPdf` | 基于指定版本生成 PDF |
| `buildRegistryMapping` | 基于指定版本生成 Registry 映射 |

统一错误类型：

- `AUTHENTICATION_REQUIRED`
- `ACCESS_DENIED`
- `VERSION_CONFLICT`
- `VALIDATION_FAILED`
- `EVIDENCE_REQUIRED`
- `LANGUAGE_INCOMPLETE`
- `PUBLICATION_LOCKED`
- `INTEGRATION_UNAVAILABLE`
- `REGISTRY_MAPPING_UNAVAILABLE`

## 15. 数据库落地建议

建议新增独立发布聚合层，不直接把现有 `product_versions` 扩大为所有职责的容器：

```text
dpp_publication
dpp_publication_review
dpp_product_publication_pointer
dpp_publication_projection_cache（可选）
dpp_publication_validation_result
```

完整快照只允许通过服务器发布函数插入；发布后拒绝更新和删除。现有 `product_versions` 在迁移期保留兼容读取，逐步降级为历史兼容表。

## 16. 不变量

系统必须持续满足以下条件：

1. 一个产品最多只有一个当前已发布版本指针；
2. 已发布快照不可更新；
3. 当前发布指针只能指向状态为 `PUBLISHED` 的完整快照；
4. 所有投影都能追溯到同一 `publicationId` 和内容 Hash；
5. 公众投影不包含高于 `PUBLIC` 的字段；
6. 未认证请求不能读取电池受限动态数据；
7. 草稿修改不改变已发布页面；
8. PDF、JSON 和 Registry 映射记录明确引用发布版本；
9. Registry、审计和区块链结果不能由普通产品表单伪造；
10. 发布失败不会替换当前有效版本。

## 17. 阶段 1 验收基线

进入业务代码重构后，至少应通过以下测试：

- 修改草稿后，公开页仍显示原发布版本；
- 发布后，九个模块均来自同一 `publicationId`；
- 公众、专业和监管投影字段数量递增且无越权；
- 中文投影不出现未授权的英文回退描述；
- PDF 与网页的关键字段值一致；
- JSON 中不出现字符串化对象；
- 二维码 URL 稳定且不包含权限提升参数；
- 电池动态数据需要登录和服务端授权；
- 已发布快照更新、删除操作被数据库拒绝；
- Registry 与区块链未配置时不产生伪成功状态。
